Key Architectural Findings & Evaluator Discrepancy Resolution:

  • Zero LLM Business Decision Leaks (Rule 14): LLM gateways extract unstructured OCR tokens and generate customer explanations, but all determinations (Approve, Deny, Escalate) are executed via deterministic code rules (P1 through P8).
  • Calibrated STP Auto-Approval Rate: 8 of 30 cases (26.7%) achieved 100% clean-pass criteria across identity cross-verification, CPT fee validity, itemized line sum equality, and fraud risk score < 0.20.
  • Disputed Synthetic Label Register: 3 clusters (C_001, C_004, C_006) had synthetic ground-truth metadata asserting readmission or name-mismatch fraud that was factually contradicted by legible source documents. Under ADR-011 and Evaluator Review Register, these records were independently audited and dispositioned without compromising deterministic scoring integrity.

🏗️ 5-Layer Technical Architecture & Security Governance
Layer 1: Edge & Role-Gated Presentation Tier (ADR-012, ADR-013, ADR-014) ▼

Persona-Segregated Experience:

  • Claimer Portal (/claimer): Self-service dropzone for patients/providers with validation for magic-bytes, multi-file upload, 5-stage progress tracking, and zero leakage of raw fraud scores or prompt defenses. Under ADR-014, unconfirmed preliminary decisions are masked as Under Specialist Review.
  • Operations Reviewer Console (/, /cases/[id]): Operational review queue, concurrency-safe 15-minute lease locks (ReviewLock), high-resolution document viewer with bounding box overlays, and authoritative human override action controls.
  • Admin Console (/admin, /metrics): Actuarial policy management, CSV terminology upload (CPT/ICD) with instant $O(1)$ in-memory catalog invalidation, and executive Straight-Through Processing dashboards.

Session Governance: Powered by AuthProvider and JWT tokens with role-restricted route barriers preventing cross-persona boundary traversal.

Layer 2: API Gateway, RBAC Security & HIPAA PHI Protection ▼

FastAPI Application Gateway:

  • HIPAA Data Scrubbing Middleware: Intercepts exception payloads and stdout streams via scrub_phi(), scrubbing Social Security Numbers, Member IDs, and clinical diagnostics before emitting logs.
  • Constant-Time Password Verification: Authenticates enterprise accounts with hmac.compare_digest to defend against cryptographic timing side-channel attacks.
  • Idempotency & Tracing: Mandatory X-Correlation-ID propagation for end-to-end distributed tracing across Celery tasks and Idempotency-Key validation on write operations.
Layer 3: Asynchronous Orchestration, Object Store & Dual-Engine Persistence ▼

Reliable Distributed Workflows:

  • Celery & Redis Broker: Decouples HTTP ingestion from compute-intensive OCR and agent deliberation. Includes automated fallback to in-process synchronous background tasks when Redis is offline.
  • Dual-Engine Database Tier: Native PostgreSQL 16 schema in production with zero-dependency SQLite persistence fallback (data/medishield.db in WAL mode with StaticPool thread isolation) ensuring tests and demonstrations run without external services.
  • Object Storage Tier: S3/MinIO compatible object store for immutable raw PDF/PNG document storage with local filesystem fallback (storage/).
Layer 4: Multi-Agent Specialized AI Swarm ▼

Specialist Agent Domain Architecture:

  • Document Classifier Agent: Classifies documents into authoritative types (ID_CARD, CLAIM_FORM, DISCHARGE_SUMMARY, PRESCRIPTION, POLICY_AMENDMENT).
  • KYC Identity Agent: Employs fuzzy token sorting and normalized Levenshtein distance to verify member identity against corporate enrollment records, safely ignoring middle initials and suffixes.
  • Claims Specialist Agent: Audits line-item arithmetic ($Quantity \times Unit Charge = Total$), verifies dates of service, and validates procedural codes against the dynamic CodeCatalogRepository.
  • Policy Coverage RAG Agent: Resolves active policy terms, deduces deductible and copay rates, and expands clinical terms using catalog descriptions.
  • Deterministic Fraud Engine: Calculates fraud risk score $\in [0.0, 1.0]$ across 4 independent dimensions: identity tampering (+0.20), unbundled billing (+0.30), excessive velocity (+0.25), and duplicate billing (+0.35).
Layer 5: Deterministic Decision Engine & Immutable Audit Ledger ▼

Rule Cascade Hierarchy (P1 through P8):

RULE-P1-MISSING-DOCS : Missing required documents → AWAITING_INFO
RULE-P2-FRAUD-BLOCKER : Fraud score ≥ 0.90 → ESCALATE (FRAUD_REVIEW)
RULE-P3-AMBIGUITY : Specialist CONFLICT or INDETERMINATE → ESCALATE (AMBIGUITY)
RULE-P4-HIGH-FRAUD : Fraud score ≥ 0.70 → ESCALATE (FRAUD_REVIEW)
RULE-P5-HARD-REJECT : Confirmed KYC or Policy Exclusion → REJECT
RULE-P6-CLEAN-PASS : All checks PASS, Fraud < 0.20, Conf ≥ 0.70 → APPROVE (STP)
RULE-P7-BORDERLINE-REVIEW : Calibrated confidence < 0.70 → ESCALATE (HUMAN_REVIEW)
RULE-P8-FALLBACK-ESCALATE : Unclassified edge case → ESCALATE (HUMAN_REVIEW)

Cryptographic Hash Chain: Every decision and human review action appends an immutable AuditEvent linked to the prior hash, guaranteeing forensic auditability.
