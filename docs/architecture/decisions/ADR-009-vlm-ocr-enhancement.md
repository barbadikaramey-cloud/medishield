# ADR-009: Vision-Language Model (VLM) for Enhanced OCR Extraction

## Status
Accepted

## Context
The current OCR engine (`rapidocr_onnxruntime`) accurately extracts bounding boxes from identification documents but occasionally struggles to accurately assemble the text for complex fields (like Member IDs and Government IDs). The user wants to improve text extraction confidence by using a Vision-Language Model (VLM).

Because this system processes sensitive information (PII/PHI), we generally avoid sending data to un-BAA'd third-party services. However, in our local development environment, all data is synthetically generated by `scripts/generate_docs.py`. The user has requested we use a free-tier VLM service (Google Gemini) strictly for local development to enhance the extraction of identity fields. 

## Decision
We will integrate the `google-genai` Python SDK to use the Gemini API (e.g., `gemini-2.5-flash`) as an enhanced extraction mechanism alongside the existing OCR engine.
- The `GEMINI_API_KEY` will be configured as an optional environment variable.
- When `GEMINI_API_KEY` is present, the VLM will be used to extract the text values of key fields (`member_id`, `first_name`, `last_name`, `dob`, `government_id_number`).
- The VLM will be instructed to return strictly structured JSON.
- The VLM output will be merged with the local bounding boxes (if available) into `ProvenanceValue` objects.
- To comply with Rule 11 & Rule 14, the VLM will *only* be used for extraction; it will not make any adjudication decisions. The final business logic in `_adjudicate_verdict` remains purely deterministic code.
- This feature is strictly for local dev/testing unless a BAA-compliant VLM is deployed for production.

## Consequences
- **Pros:** Significantly higher accuracy for field extraction, particularly for Member IDs and Government IDs.
- **Cons:** Introduces a dependency on an external API, with latency and rate limits. Requires careful handling to ensure we don't accidentally send real PII to a non-compliant service in production.
